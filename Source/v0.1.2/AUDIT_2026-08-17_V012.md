# Stream Doctor v0.1.2 — Re-audit Record

Date: 2026-08-17 JST
Target: Kodi 22 "Piers", Windows first
Safety mode: read-only

## Purpose

Fresh re-audit of the v0.1.1 physical-validation candidate. The pass deliberately looked beyond the existing test suite for contradictory telemetry, false-positive diagnosis paths, privacy boundary failures, report corruption handling, source/session boundary errors, and package-version inconsistencies.

## Problems found and fixed

1. Internal library version was stale at 0.1.0 while addon.xml was 0.1.1. v0.1.2 now has a QA-enforced version consistency check.
2. Runtime confirmed video playback and the sensor immediately queried `isPlayingVideo()` a second time. A transient exception could create a contradictory non-playing sample. Runtime now passes the already-known playback state into the sensor.
3. Boolean telemetry exceptions could collapse "unknown" into `False`, particularly hardware-decoder state. Optional boolean reads are now tri-state.
4. One transient queue/bitrate dip could be retained as a high-confidence starvation event. Delivery and audio starvation now require sustained consecutive evidence unless a fresh user problem marker corroborates the event.
5. Low free-memory percentage alone could mark a smooth stream degraded. Memory diagnosis now uses absolute free MB when available, and uncorroborated low memory is a low-severity headroom risk rather than a causal playback claim.
6. A 50/50 boolean summary was silently resolved to `True`. Ties now remain unknown.
7. Two isolated Kodi Internet-state blips could support a high outage diagnosis. Outage attribution now requires sustained overlap with starvation (or a fresh user marker).
8. Stream identity depended too heavily on Player.Folderpath. Channel/provider metadata now provides a privacy-preserving fallback when the path is missing, improving PVR channel-change session separation.
9. Malformed URL ports could send identity normalization down a less safe fallback. Malformed credential-bearing URLs are now normalized without retaining raw credentials/query/fragment in identity material.
10. Generic `pvr://` origin labels were too coarse for historical source attribution when provider metadata was absent. History now refuses that unsupported attribution.
11. Report loading could let a corrupt/oversized newest file hide older valid reports. Storage and UI now skip invalid/oversized files and continue to the latest valid report.
12. Storage privacy depended mainly on upstream field sanitization. The report writer now independently redacts secret-like values, strips ephemeral source keys, and re-sanitizes source origins as defense in depth.
13. QA did not CRC-test every ZIP member or enforce internal/package version agreement. Both gates are now mandatory.
